# Snippet sharing assumptions

These are assumptions to validate, not claims that research has proved them.

- Developers keep snippets mostly for themselves, so a new snippet should start
  private and become shared only by a deliberate choice.
- Sharing a snippet with one colleague (an unlisted link) and putting it out
  for anyone to find and reuse (public) are different intentions, and people
  expect the Product to keep them apart.
- Language and tags are how people find their own snippets again; a title
  alone is not enough once there are dozens.
- People who reuse someone else's snippet want a copy of their own to change,
  not permission to change the original.
- A visible history makes owners more willing to improve a snippet they have
  already shared, because the earlier code is not lost.
- Writing a description and tags is the step people skip. A suggestion they
  can accept or edit in one step increases how many snippets are described,
  provided it never changes the code and never saves anything on its own.

Future research may change the Product Model; this file does not override it.
