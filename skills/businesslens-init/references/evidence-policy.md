# Evidence policy

- Trace every material behavioral claim to repository evidence.
- Prefer implementation and tests over marketing copy.
- Use documentation to discover behavior, then confirm it in routes, handlers,
  services, models, configuration, or tests where practical.
- Store repository-relative paths. Add a symbol when it improves verification.
- Do not invent line numbers.
- Treat generated files, fixtures, vendored code, and translations as
  low-signal unless they are the only evidence.
- Record conflicting or ambiguous evidence as a limitation.
- Never claim live operational values from source code alone.
